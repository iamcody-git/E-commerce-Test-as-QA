# E-commerce Testing – Jira Project Setup

## 1. Project Overview

**Project Name:** E-commerce Testing
**Jira Project Key:** ECT
**Project Type:** Software Project
**Testing Focus:** Manual QA / Functional Testing

This Jira project was created to practice and demonstrate a real-world QA workflow for an e-commerce application.

The project covers key e-commerce functionalities such as user authentication, shopping cart, and payment.

---

## 2. Project Objectives

The main objectives of this project are:

* Practice Jira project and issue management
* Create and manage Epics, Stories, Tasks, and Bugs
* Track testing activities through Jira
* Practice defect reporting and tracking
* Manage work using a Jira board
* Understand issue priorities and statuses
* Maintain a structured QA workflow
* Create a portfolio project that demonstrates practical Jira skills

---

## 3. Epics

The current project contains the following Epics:

| Epic                           | Description                                                           |
| ------------------------------ | --------------------------------------------------------------------- |
| **User Registration and AUTH** | Registration, login, logout, and authentication-related functionality |
| **Shopping Cart**              | Adding, removing, and managing products in the shopping cart          |
| **Payment**                    | Checkout and payment-related functionality                            |

---

## 4. Work Items

The project currently contains **13 work items**.

The work items include:

* Stories
* Tasks
* Bugs

### Examples

**User Authentication**

* User can register with valid information
* Login with valid credential
* User can log out smoothly
* User receives an error for invalid login credential

**Shopping Cart**

* User can add a product to cart
* User can remove a product from cart
* Test cart price calculation on update
* Product can be added to cart even if it is out of stock

---

## 5. Jira Board

The project uses a board to track the progress of work items.

Current board statuses:

```text
To Do → In Progress → In Review → Done
```

Each work item is moved through the workflow according to its current testing/development status.

---

## 6. Priorities

Issues are assigned priorities according to their impact on the application.

Examples:

* **Highest/Critical** – Major functionality failure or serious business impact
* **High** – Important functionality affected
* **Medium** – Normal functional issue
* **Low** – Minor UI or usability issue
